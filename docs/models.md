# MongoDB / Mongoose model reference

These models define persistence and validation boundaries only. They do not implement API routes, authentication, bank connectivity, or regulatory policy. Workflow vocabularies and role names are application placeholders for stakeholder review; no AICTE rule or maturity threshold is encoded.

## Trust and tenant boundaries

- `institutionId` is stored on every institution-owned document and is immutable after creation. It must be assigned from authenticated server-side membership context, never copied from a client DTO.
- Use `institutionScopedFilter()` for tenant-owned reads and combine the institution predicate outside caller-supplied filters. A valid `institutionId` does not itself prove the actor is a member; authorization must resolve the actor's membership first.
- Check that every referenced instrument, document, user, renewal, and extraction belongs to the same institution before linking records. MongoDB references do not enforce tenant consistency.
- Zod command schemas use strict allowlists. Workflow summaries, actor IDs, storage keys, OCR provider results, review outcomes, verification results, and compliance states are absent from public create/update shapes. Their values are set by authorized services after policy checks.
- Mongoose `strict: 'throw'` rejects unknown properties and `immutable` protects selected history/provenance fields in document updates. Neither feature replaces service authorization; code with direct database access remains trusted.

## Validation and indexes

`validators/model-schemas.ts` defines explicit Zod command schemas and exported inferred input types. Dates arriving from JSON use `YYYY-MM-DD` and are checked as real calendar dates. FDR create validates maturity after issue and validity not before maturity; partial updates must be merged with the stored record and validated again before saving. Amounts arrive as positive decimal strings with at most two fractional digits and are converted to `Decimal128` in the service. Request schemas are strict so attempted extra fields such as `institutionId`, `reviewStatus`, `verificationStatus`, `mode`, `storageKey`, `reviewerId`, or `actorId` are rejected.

Tenant query indexes support institution + maturity date, institution + review status, institution + verification status, instrument/document history, and notification/audit timelines. The FDR internal reference is unique only within an institution. Verification idempotency is unique per adapter and key. These indexes improve lookup and consistency; they do not provide authorization on their own.

Configured reminder rules carry a value, unit, effective dates, version, source, and optional assumption label. Values are intentionally not seeded: owners must approve each rule and its source before activation.
